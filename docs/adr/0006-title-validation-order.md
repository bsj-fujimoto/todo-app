# ADR-0006: タイトルの検証順は「必須 → 長さ → 改行」とする（UNK-001）

- 状態: 採用（2026-10-11）
- 決定者: QA リード（UNK-001 の回答担当ロール）。契約への記載は PR #2、承認はプロダクトオーナー（PR のマージをもって承認。フェーズ1は AI が代行マージ）
- 関連: 未決 UNK-001（`docs/data/unknowns.csv`、resolved）、REQ-031、`backend/openapi.yaml` の `TitleInvalid`、`backend/src/domain/title.js`、`frontend/src/validation.js`、TC-029、VIEW-063

## 背景

仕様書 v1.1 の §04 は、タイトルの規則（必須・100 コードポイント以内・改行不可）を定めているが、**複数の違反が重なったときにどのエラー文言を出すか**は定めていない。
たとえば「空白と改行だけ」「50 文字 + 改行 + 60 文字」のような入力は、必須・長さ・改行のうち複数に当たる。
検証順が実装ごと（frontend と backend、または実装者）にぶれると、同じ入力で画面と API が別の文言を返し、RISK-002（検証抜け・誤判定）と RISK-008（API 契約逸脱）になる。

## 決定

- 検証順は **必須 → 長さ → 改行**とし、**1 回の検証で返すエラーは 1 つだけ**にする。
- 判定は、**前後の空白を除去した後**に行う（REQ-030。「前後の空白」の範囲は暫定で JavaScript の `trim()`、UNK-006 で確定）。
- 結果:
  - 空白のみは、除去後に空になるため `TITLE_REQUIRED`「タスク名を入力してください」。
  - 101 文字 + 改行は、長さが先に判定され `TITLE_TOO_LONG`「タスク名は100文字以内で入力してください」。
  - 100 文字以内で改行を含むときだけ `TITLE_MULTILINE`「タスク名は1行で入力してください」。
- 正本は `backend/openapi.yaml` の `TitleInvalid`（API 契約）。frontend の表示（`validation.js`）も同じ順にする。文字数は Unicode コードポイント単位で数える（サロゲートペア・結合文字を丸めない）。

## 影響

- 画面と API が同じ入力に同じ文言を返す。テスト（TC-029 ほか）が検証順を固定し、変更すると契約テストと unit が落ちる。
- 検証順を変える場合は、openapi.yaml・backend・frontend・TC-029・本 ADR を同じ PR で変える（`docs/03-test-spec.md` §14.3 の影響ケースの特定に従う）。
- 限界: 「複数の違反をまとめて表示する」仕様にはなっていない（利用者は 1 つ直すと次のエラーが出ることがある）。仕様書 v1.1 は最初の違反だけを表示する前提で、UX の改善はフェーズ1の範囲外。

## 却下した案

| 案 | 却下の理由 |
|---|---|
| 長さ → 必須 → 改行 | 空文字は長さ 0 で長さの検査を通ってしまい、「入力してください」を出せなくなる |
| 改行を先に判定する | 101 文字 + 改行 の入力に「1 行で」と出す。契約（`TitleInvalid`）は長さが先と規定し、UNK-001 の回答もそれに従う。改行だけを直すと次に長さのエラーが出る二度手間になる |
| 違反をすべてまとめて返す | 仕様書 §04 とエラー表示（入力欄の直下に 1 つ）の画面仕様を変える必要があり、AC の変更になる |
| 実装に任せ、検証順を決めない | 画面と API で文言がぶれる（RISK-002・RISK-008）。テストで固定できない |
